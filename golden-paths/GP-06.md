# GP-06 — Multi-App Platform

Dos o más clientes reales comparten dominio, contratos y backend.

- Default: `hono-api` + `tanstack-admin`.
- Alternativa: FastAPI cuando Python/IA domina el backend.
- Surfaces componibles: `public-intake` (provider `tanstack-transactional-pwa` en `apps/intake`), `mobile` (provider Ignite en `apps/mobile`) y `desktop` (provider `tauri-ui` en `apps/desktop`), desde el intake o después con `eng surface add`.
- Datos: PostgreSQL.
- Features iniciales: auth, RBAC, audit, API keys y observability.
- Gates: contrato, integración y migración además de los gates normales.
- Evitar: reglas duplicadas por cliente, backends por pantalla o microservicios prematuros.
- Elegir cuando haya dos o más clientes (dashboard + portal público/kiosco/móvil/escritorio), o uno más otro futuro explícito: la Recipe se elige por el futuro aunque las surfaces iniciales queden vacías; todas comparten la misma API.

Ejemplo: administración web y aplicación móvil consumen la misma API y contratos.
