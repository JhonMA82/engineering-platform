# Casos de uso por sector

## Gobierno

- Portales públicos: Stardrive.
- Atención y trámites: Institutional Operations Starter + TanStack o SpeedPy.
- Padrones y reportes: SpeedPy.
- API para múltiples canales: FastAPI.
- Turnos y pantallas en vivo: piloto GoShip.
- Inspecciones móviles: Ignite.
- Automatización: n8n con código para reglas críticas.
- Asistente normativo: AI Assistant Starter con citas y auditoría.

## Escuelas

- Sitio institucional: Stardrive.
- Control escolar: SpeedPy o Institutional Operations Starter.
- Portal administrativo: TanStack Admin.
- App de alumnos/tutores: Ignite.
- Importación de listas y calificaciones: SpeedPy.
- Asistente de reglamentos: AI Assistant Starter.
- Producto vendido a múltiples planteles: Open SaaS solo después de diseñar tenancy.

## Sindicatos

- Portal y comunicados: Stardrive.
- Padrón de afiliados: SpeedPy.
- Gestiones y expedientes: Institutional Operations Starter.
- App de beneficios/credencial: Ignite.
- Consulta de convenios: AI Assistant Starter.
- Notificaciones en tiempo real: evaluar GoShip o servicio existente.

## Pymes

- Sitio y contenido: Stardrive.
- CRM/operación: TanStack Admin + backend adecuado.
- Herramientas de Excel: SpeedPy Lite.
- SaaS propio: Open SaaS.
- App móvil de campo: Ignite.
- Utilidad de escritorio: Tauri UI.
- Integraciones: FastAPI/Python Service + n8n.
- Copiloto interno: AI Assistant Starter.

## Patrón común

La selección se hace por la forma del problema, no por el nombre del sector. Una escuela y una pyme pueden necesitar la misma arquitectura si ambas procesan Excel y aprobaciones.
